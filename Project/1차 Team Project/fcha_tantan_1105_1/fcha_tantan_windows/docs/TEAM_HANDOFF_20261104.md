## 4. 이번 대화에서 추가·수정한 1:1 채팅

### 사용 흐름

1. 등록자: 내 양도양수 → 받은 문의 확인 → 문의별 `1:1 채팅`.
2. 문의자: 내 양도양수 → 보낸 문의 → `1:1 채팅`.
3. 기존 문의 내용을 첫 메시지로 보여주며, 이후 답장을 같은 문의의 대화 내역에 저장합니다.

### 서버·권한

- 문의 1건당 하나의 대화 흐름입니다. 같은 매물에 같은 사람이 문의를 여러 번 보내면 문의별로 별도 대화가 됩니다.
- URL 이름: `market:transfer_chat`, 경로: `/market/transfer/chat/<문의 PK>/`.
- 로그인한 등록자와 해당 문의자만 조회·전송할 수 있습니다. 제3자는 404로 차단합니다.
- 새 모델 `TransferChatMessage`: 문의 FK, 작성자 FK, 메시지 본문, 작성 시각. 작성 시각과 PK 순으로 조회합니다.
- 메시지 최대 1,000자, 공백 메시지 거부, 서버 검증·CSRF 적용, 템플릿 HTML 이스케이프 적용.
- 등록자가 채팅에 들어오면 기존 문의가 읽음 처리됩니다.
- 마이그레이션: `0016_transferchatmessage.py`. 현재 작업 DB에는 적용 완료입니다.

### 채팅 화면·동작

- 당근·카톡과 유사한 대화 구조: 상대방 이름·이니셜 헤더, 매물 바로가기, 좌우 말풍선, 날짜·시간 표시.
- 내 메시지: 오른쪽 연한 주황색. 상대방 메시지: 왼쪽 흰색.
- 대화 영역만 스크롤하고 입력창은 채팅 패널 하단에 유지합니다.
- `fetch`로 메시지를 전송하여 전체 페이지 새로고침 없이 대화 내역을 갱신합니다.
- 새 메시지는 5초 간격으로 조회합니다. WebSocket 방식은 아닙니다.
- 이전 대화를 읽는 중에는 스크롤을 유지하고 `새 메시지 ↓` 버튼으로 최신 위치로 이동합니다.
- PC의 정밀 포인터 환경에서는 Enter 전송, Shift+Enter 줄바꿈. 모바일에서는 전송 버튼을 사용합니다. 한글 조합 중 Enter 오작동을 방지합니다.
- 입력 내용에 맞춰 입력창 높이를 조절하고, 전송 중 중복 제출을 막으며, 실패 시 입력을 유지하고 안내합니다.

## 6. 다른 팀원 PC에 적용

1. 현재 작업 프로젝트의 코드를 전달하되, 실행 경로 혼동을 피하도록 중첩 폴더 구조를 명확히 알립니다.
2. 팀원의 기존 `db.sqlite3`, `.env`, 업로드 파일을 백업하고 보존합니다. 코드 업데이트 때문에 팀원의 최신 DB를 첨부 DB로 덮어쓰지 마세요.
3. 사용하는 가상환경에서 의존성을 준비하고 마이그레이션 후 실행합니다.

```powershell
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py check
python manage.py runserver
```

4. 배포 서버는 기존 정적 파일 배포 절차에 따라 `collectstatic` 적용 여부를 확인합니다.
5. 화면 캐시가 남으면 Ctrl+F5로 갱신합니다.

채팅은 HTML 파일만 복사해서 적용할 수 없습니다. 모델·뷰·URL·마이그레이션을 함께 전달해야 합니다. 비밀 설정 값은 이 문서에 포함하지 않았습니다.
