# 지역상권분석 대시보드 적용 안내

## 실행

기존 프로젝트를 백업한 뒤 수정본을 적용하세요. 프로젝트 폴더에서 실행합니다.

```bat
python manage.py migrate
python manage.py runserver
```

로그인 후 `/brands/bregion/`에서 확인합니다. 실제 URL은 프로젝트의 brands URL 연결을 따릅니다.
신규 마이그레이션: `market/migrations/0005_dashboard_preferences.py`.
압축본의 기존 DB·환경설정·이미지·나머지 파일은 보존했습니다. DB에 임의 통계나 가상 브랜드를 입력하지 않았습니다.

## 화면 변경

- 기존 브랜드 색상 변수와 로고·공통 메뉴 유지.
- 왼쪽: 위치, 총예산, 업종, 반경, 주 고객 연령대, 선호 상권, 점포 확보 여부, 운영 방식.
- 오른쪽: 유동·상주·직장인구, 공식 상권 유형, 지도, 연령 분포, 브랜드 후보.
- 월세 상한, 브랜드 인지도 선호, 토지이용 현황 없음. 좌표·위치정밀도는 사용자 입력 화면에서 제외.
- 기존 월세 값은 숨김 필드로 보존하며 다른 페이지의 월세 기능은 유지.
- 기존 브랜드 비교와 소비·개폐업 자료는 펼쳐보기로 유지.
- 자료가 없으면 미연결로 표시. 0은 0으로 표시.

## 출력에 필요한 데이터

| 화면 | 필요한 항목 | 기존 저장 위치 | 상태·주의 |
|---|---|---|---|
| 나의 창업 조건 | 사용자, 희망 위치, 총예산(만원), 업종, 반경(m), 확보 여부, 운영 방식 | `StartupCondition` | 기존 조건 저장·삭제 사용 |
| 주 고객 연령대 | 선택 연령대 목록 | `StartupCondition.target_ages` | 이번에 추가. 실제 지역 인구 분포와 구분 |
| 선호 상권 | 회사·주거·상가 선택 목록 | `StartupCondition.preferred_area_types` | 이번에 추가. 실제 밀집도와 구분 |
| 선택 위치·반경 | 주소, 위도, 경도, 반경 | `StartupCondition.latitude/longitude/radius_m` | 주소 검색 때 좌표 자동 수집. 좌표값을 화면에서 직접 입력하지 않음 |
| 지도 | 카카오 JavaScript 키, 허용 도메인, 지도 SDK | `.env`의 `KAKAO_JS_KEY` | 키·도메인 설정 필요. 회사·주거·상가 영역 색칠은 실제 경계 데이터 없어서 생성하지 않음 |
| 지도 등록 매장 | 브랜드, 주소, 좌표, 공개 동의·인증 상태 | 기존 `StoreLocation` 및 지도 API | 기존 지도 연결 유지. 공개 인증 점주 매장만 집계하므로 전체 업소 수가 아님 |
| 전국 장소검색 | 검색어, 지역 또는 지도 범위, 장소 이름·좌표·주소 | 기존 카카오 Places 검색 | 최대 45개 지도 표시. 전체 매장 수로 사용하면 안 됨 |
| 공식 분석구역 | 상권코드, 이름, 유형, 행정구역코드, 경계 GeoJSON, 버전, 기준일, 검증 여부 | `CommercialArea` | 좌표가 검증된 상권 하나에 포함될 때 통계 연결 |
| 인구 요약 | 상권, 기간, 인구 종류, 총인구, 단위 | `PopulationStat` | `floating` 유동 / `resident` 상주 / `worker` 직장. 단위·기간을 원문대로 표시하므로 일평균이라고 임의 해석하지 않음 |
| 연령 분포 | 유동인구 연령별 수치 | `PopulationStat.by_age` | 제공된 0 이상 숫자 합계로 비중 계산. null은 제외하며 누락 연령을 0으로 채우지 않음. 같은 단위·기간의 자료만 입력 |
| 상권 유형 | 공식 자료의 상권 분류 | `CommercialArea.area_type` | 회사·주거·상가 밀집도를 계산한 값이 아님 |
| 회사·주거·상가 밀집도 분석 확장 | 사업체·종사자 수, 주거인구·가구 수, 영업 점포 수, 구역 면적, 기간, 구역 코드 및 밀집도 분류 기준 | 기존 `PopulationStat`, `StoreTrend`, `Attractor` 등 원자료 활용 가능 | 현재 화면은 자동 밀집도 판단·색칠·적합도 점수 미제공. 분류 기준과 같은 구역·기간 자료를 먼저 정해야 함 |
| 브랜드 후보 | 브랜드 ID·이름·업종·이미지·공시연도·창업 부담금 | `Brand`, `AnnualStat` | 예산과 업종으로 기존 후보 로직 사용. 공시 비용 미확인 후보는 미제공으로 표시 |
| 운영 조건 확인 | 최소 면적, 필요 인원, 직원 운영 가능 여부, 판매 방식, 제한 사항 | `BrandOperation` | 입력·확인된 조건만 후보 필터에 사용. 지역 적합도 순위 아님 |
| 브랜드별 비교 | 지역·전국 매장 수, 공시연도, 지역 매출 범위 | `AnnualStat`, `RegionalStat` 및 기존 등록 매장 집계 | 지역 상세 등록 매장 수와 시도 공시 매장 수를 구분 |
| 소비 수요 상세 | 상권, 업종 코드, 매출액·건수, 기간·단위 | `IndustrySales`, `IndustryCode` | 상세 펼쳐보기 유지 |
| 개폐업 상세 | 상권, 업종, 영업·개업·폐업 수, 기간·단위 | `StoreTrend` | 상세 펼쳐보기 유지 |
| 출처 표시 | 자료명, 원문 URL, 수집일, 비고 | `DataSource` | 각 자료는 출처와 통계 기준기간을 함께 관리 |

자료 연결 기준은 브랜드명만이 아니라 브랜드 ID, 공식 상권코드와 경계 버전, 업종 코드 체계·버전, 기준기간입니다.
서로 다른 구역·기간 자료를 합산하거나 공식 상권 통계를 500m 반경 통계로 표시하지 않습니다.
주 고객 연령대와 선호 상권은 저장하지만 현재 추천 점수·필터에는 반영하지 않습니다. 검증된 지역 적합도 계산 없이 결과를 만들어내지 않기 위해 화면에 안내했습니다.

## 수정 파일

- `brands/templates/bregion.html`: 대시보드 배치
- `brands/templates/includes/region_candidates.html`: 브랜드 후보 카드
- `static/css/region_dashboard.css`: 페이지 전용 스타일
- `static/js/analysis.js`: 기존 조건 입력 처리와 대시보드 연결
- `static/js/maps.js`: 저장 위치·반경 표시
- `market/analysis_models.py`, `market/analysis_forms.py`: 연령대·선호 상권 저장
- `market/analysis.py`: 연령 분포와 브랜드 비용 표시용 데이터
- `market/migrations/0005_dashboard_preferences.py`: 신규 필드 추가

## 검증

Django 시스템 검사, 격리 DB에서 마이그레이션 및 페이지 출력, 조건 저장·수정·삭제, 선택값 보존, 미제공·0 표시 검증, JavaScript 문법 검사 통과.
첨부 원본 DB 복사본에서도 마이그레이션 적용 검증 완료. 원본 DB 바이트는 변경하지 않았습니다.
카카오 키의 실제 도메인 연결·주소검색 및 외부 지도 검색 결과는 이 환경에서 실서비스 검증하지 않았습니다.

브라우저 실행 파일을 확보할 수 없어 실제 화면 스크린샷 검수는 수행하지 못했습니다. 템플릿 출력과 반응형 CSS 구성은 확인했으며, 브라우저 외부 지도 기능은 실행 후 확인이 필요합니다.
