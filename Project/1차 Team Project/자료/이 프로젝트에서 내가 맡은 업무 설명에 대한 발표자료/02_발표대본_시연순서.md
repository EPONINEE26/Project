# 7분 발표 대본과 시연 순서

## 0:00~0:40 — 목적

“제가 맡은 부분은 프랜차이즈의 매출·점포 수를 비교하고 비용 입력에 따른 예상 운영이익을 계산하는 데이터 분석입니다. 치킨·커피·편의점·이미용의 선정19개 브랜드를 대상으로,2024년과2025년, 서울·경기와 전국을 구분했습니다. AI의 도움을 받아 코드를 구성했으며 오늘은 수집부터 분석·저장·검증까지의 동작을 설명하겠습니다.”

보여 줄 것: 설명서의 1번 또는 업종별 엑셀의 시트 목록.

## 0:40~1:40 — 수집

“처음부터 모든 값이 웹에서 자동 수집된 것은 아닙니다. 기존 엑셀을 바탕으로 공개 웹 표를 수집하고 부족한 값을 대조해 보완했습니다. Python의 urllib로 공정위 브랜드 검색 화면을 요청했고, 상세 페이지를 찾은 다음 HTMLParser로 표의 행과 칸을 뽑았습니다. 검색에서 상세로 이동할 때는 쿠키를 유지했습니다. 비슷한 브랜드 이름이 있으므로 브랜드명도 대조했습니다.”

보여 줄 것: reference_code/fetch_ftc.py의 `build_opener`, `op.open` 부분. HTMLParser 전체 코드를 전부 읽을 필요는 없습니다.

## 1:40~2:30 — 연도·단위 정리

“웹에서 받은 숫자는 쉼표가 있는 문자열일 수 있어 숫자로 바꿨습니다. 예를 들어CU의2024년 평균매출633,837천원을 원으로 바꾸면633,837,000원입니다.2025년 등록 공시에2024년 실적이 있을 수 있으므로 공시일과 실적연도를 구분했습니다. 가맹점과 직영점도 구분했습니다.”

보여 줄 것: 노트북 2~3단계의 CU 공시표와 원 단위 변환 결과.

## 2:30~3:20 — 원본 보존

“수집값을 아무 곳에 넣는 것이 아니라 브랜드·연도·지역에 맞춰 연결했습니다. 이미 값이 있는 셀은 그대로 두고, 빈 셀에 넣을 값과 출처를 보완계획으로 만들었습니다. 엑셀은 기존 시트·수식·서식을 보존하기 위해 복사 후 지정 셀만 바꾸는 방식으로 저장했습니다. 따라서 원본을 새 표로 전부 다시 만드는 방식과 다릅니다.”

보여 줄 것: 원본 보존 코드의 `_blank`, `fill_only_blanks` 함수 이름과 출처가 있는 보완계획 형식.

## 3:20~4:10 — 분석

“pandas로 연도·업종·브랜드·지역·값을 가진 표를 만들었습니다. 같은 연도·지역만 먼저 선택하고 groupby로 업종별 평균을 계산했습니다. rank로 같은 업종의 매출 순위를 구하고, merge로 동일 브랜드의 두 연도를 연결해 전년 비교를 만들었습니다. 이 평균은 선정 브랜드의 단순평균이며 전체 시장의 공식 평균은 아닙니다.”

보여 줄 것: 노트북 6~8단계. 결과값을 전부 읽지 말고, 어떤 조건으로 묶었는지 설명하세요.

## 4:10~5:10 — CU 예상 운영이익

“CU 연평균매출633,837,000원에 원본 편의점 비용 비율을 적용했습니다. 재료비65%, 인건비8%, 임차료5%, 기타5%를 더하면 운영비 비율83%입니다. 운영비는526,084,710원, 예상 운영이익은107,752,290원, 이익률은17%입니다. 여기서 비용은 실제 지출 공시를 수집한 값이 아니라 시뮬레이션 가정입니다. 실제 사용자가 비용을 입력하면 예산 함수가 그 금액으로 다시 계산합니다.”

보여 줄 것: 노트북 9단계의 표. 이어 10단계에서 임차료를100만원 더 입력했을 때 이익이100만원 줄어드는 검증을 보여 주세요. 이 변화는 기능 검사이며 실제 임차료 조사 결과가 아닙니다.

## 5:10~6:10 — 엑셀 수식과 JSON

“엑셀은 수식과 마지막 저장 계산값을 함께 가집니다. 수식이 있어도 저장 결과가 비어 있으면 뷰어에서 빈칸으로 보일 수 있어 이 부분을 별도 검증했습니다. JSON 변환은 openpyxl로 수식과 저장 결과를 각각 읽고 json으로 저장했습니다. 사람이 보는 엑셀과 프로그램이 읽는 JSON을 함께 제공하기 위한 작업입니다.”

보여 줄 것: 노트북 11단계의 수식·값 비교표,12단계 JSON 변환 검증 결과.

## 6:10~7:00 — 검증과 한계

“기존값을 덮어쓰지 않았는지, JSON 값이 엑셀과 같은지, 비용 변화가 이익에 반영되는지 확인했습니다. 다만 원본 보존을 검증했다고 모든 원본 수치가 공식 자료와 일치한다는 뜻은 아닙니다. 또 이전 분석용JSON과 마지막 엑셀 보존용JSON은 구조가 달라 연결 과정이 필요했습니다. 오늘 실습은 이 연결을 분리한 오프라인 시연입니다. 자료가 없는 연도의 숫자를 임의로 생성하지 않았다는 점도 구분했습니다.”

보여 줄 것: 실습_검증결과.txt.

# 가장 안전한 시연 순서

1. 압축을 풀고 폴더 전체를 VS Code로 엽니다.
2. `03_발표_실습.ipynb`를 엽니다.
3. 사용 중인 Python 커널을 선택합니다.
4. 첫 코드 셀부터 위에서 아래로 실행합니다. 입력 폴더를 찾지 못하면 노트북이 있는 폴더를 기준으로 열었는지 확인합니다.
5. 시간이 부족하면 2~3단계,6단계,9~10단계,11~12단계를 보여 줍니다. 뒤 셀은 앞 셀의 변수를 사용하므로 실행 자체는 위에서부터 해야 합니다.
6. 온라인 수집은 사이트 응답·접근 오류 가능성이 있어 실시간 성공을 약속하지 않습니다. 발표에서는 이미 수집한 근거 자료와 수집 코드를 함께 보여 주는 방식이 안전합니다.
7. 실습은 원본 엑셀과JSON을 읽고 `demo_output/`에 새 결과를 씁니다. 기존 데이터를 덮어쓰지 않습니다.

필요 패키지가 없을 때, 사용 중인 Python 환경의 터미널에서 설치합니다.

```bash
python -m pip install pandas openpyxl
```

API 서버 시연은 이 실습의 필수 과정이 아닙니다. 기존 api.py는 이전JSON구조를 읽으므로 새변환JSON을 무작정 폴더에 복사하지 마세요. 사이트 접속이나 서버 오류를 해결하는 시간을 발표 본문에 넣지 않는 편이 좋습니다.
