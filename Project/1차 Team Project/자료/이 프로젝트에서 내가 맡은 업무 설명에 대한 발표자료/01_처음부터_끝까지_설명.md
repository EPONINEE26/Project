# 프랜차이즈 분석: 실제 구현 과정과 발표 설명

## 먼저 구분할 사실

이 프로젝트는 **기존 엑셀을 입력 자료로 사용하고, 웹에서 수집·대조한 자료로 빈칸을 보완한 뒤 분석한 작업**이다. 사이트의 모든 자료를 한 번에 자동 수집해 완성본까지 만드는 단일 프로그램은 아니다.

수집 대상에는 공정거래위원회 가맹사업거래 공개 표가 있다. 이전 조사에서는 점포가이드(jumpo.shop)의 공시 이력 및 공개 정보공개서 PDF도 대조했다. 현재 확인한 배포 코드에서 공식 사이트 수집을 맡는 파일은 `fetch_ftc.py`, 일반 HTML 표 파싱을 맡는 파일은 `scrape.py`다. 점포가이드 이력 추출 및 PDF 대조는 별도 조사 단계였으며, 이 배포 코드 하나가 그 조사까지 모두 자동 수행한다고 말하면 안 된다.

최초 엑셀의 기존 숫자까지 전부 이번 스크래핑으로 얻었다고 주장할 수 없다. 기존값은 첨부 원본에서 온 값이며, 보완값에는 별도 출처를 연결했다. 원본 보존과 원본의 정확성 보증도 서로 다르다.

이 설명은 회수한 실제 코드와 파일을 읽고 확인했다. 외부 함수의 의미는 Python·pandas·openpyxl 공식 문서와 대조했다. 과거 수집 자료의 숫자를 오늘 다시 조사한 최신 숫자로 표현하지 않는다.

## 1. 무엇을 만들려고 했는가

대상은 치킨·커피·편의점·이미용 4업종, 총19개 선정 브랜드다. 편의점4개, 나머지 업종은 각5개다. 기간은2024·2025년이며 서울·경기와 전국 수치를 구분한다.

다음 질문에 답하는 것이 목적이다.

1. 같은 연도에 어느 브랜드의 점포당 평균매출이 높은가?
2. 서울과 경기의 매장 수 및 점포당 평균매출이 어떻게 다른가?
3. 선정 브랜드들의 업종별 평균매출은 얼마인가?
4. 주어진 비용을 지출하면 예상 운영이익은 얼마인가?
5. 결과를 사람이 엑셀로 보고, 프로그램은JSON으로 읽을 수 있는가?

**점포당 연평균매출은 전국 전체 점포 매출의 합계가 아니다.** CU633,837,000원은 여기서 사용한2024년 전국 기준 가맹점당 연평균매출이다. CU본사 매출이나 모든CU 점포의 총매출이라고 설명하지 않는다.

## 2. 웹스크래핑은 무엇이며 어떻게 시작했는가

웹페이지는 화면 뒤에HTML이라는 글자 형태의 문서가 있다. 스크래핑은 그 문서를 요청해서 받고, 필요한 표의 내용을 뽑아내는 작업이다.

실제 `fetch_ftc.py`는 브랜드 검색 화면을 요청하고, 검색 결과에서 해당 브랜드의 상세 페이지 주소를 찾는다. 이후 상세 페이지와2025년에 등록된 과거 공시 중 하나를 요청한다. 여기서2025년 등록 공시와2025년 실적은 다를 수 있다.

실제 사용한 핵심 부분:

```python
op = urllib.request.build_opener(
    urllib.request.HTTPCookieProcessor(http.cookiejar.CookieJar())
)
op.addheaders = [('User-Agent', 'Mozilla/5.0')]
```

- `urllib.request`: 웹주소에 요청을 보내고 응답을 받는 Python 기본 도구다.
- `build_opener`: 요청을 보낼 도구를 만든다.
- `CookieJar`: 사이트가 응답으로 준 쿠키를 보관한다.
- `HTTPCookieProcessor`: 다음 요청에 필요한 쿠키를 다시 전달한다.
- 쿠키는 검색 화면을 거쳐 상세 화면으로 이동하는 동안 같은 방문의 연결을 유지하는 데 사용했다. 이것이 로그인이나 모든 접근 제한을 해결한다는 뜻은 아니다.
- User-Agent는 요청에 실어 보내는 클라이언트 정보다. 이를 지정했다고 실제 브라우저가 실행되는 것은 아니다.

```python
raw = op.open(listurl, timeout=30).read().decode()
```

- `listurl`: 브랜드 검색URL이다.
- `open`: 요청을 보낸다.
- `timeout=30`: 연결 등이 오래 걸리면 무한히 기다리지 않도록 제한한다. 모든 작업이 반드시30초 이내 끝난다는 뜻은 아니다.
- `read()`: 응답 바이트를 읽는다.
- `decode()`: 바이트를 문자열로 바꾼다. 해당 코드는 기본UTF-8 해석을 사용하며 모든 사이트 인코딩을 자동 해결하는 코드는 아니다.

사이트에는CU와 비슷한 이름의 다른 브랜드도 있다. 코드에서는CU는`씨유(CU)`, 이마트24는`이마트24(emart24)`처럼 이름을 대조했다. 이 부분이 빠지면 다른 회사의 자료를 가져올 수 있다. 다만 일부 브랜드의 정확 일치 후보가 없을 때 부분 일치 후보를 사용하는 경로도 있어, 이름 대조가 모든 경우를 완벽하게 보장한다고 말하지 않는다.

**발표 문장:** “브랜드별 검색 페이지를 요청하고, 검색 결과의 브랜드명을 대조한 다음 상세 페이지의 공개 표를 수집했습니다.”

## 3. HTML에서 표를 어떻게 꺼냈는가

`HTMLParser`를 상속한 `TableParser`가 HTML의 표를 읽는다. HTML에서 `table`은 표, `tr`은 한 행, `th`와`td`는 한 칸이다.

실제 일반 수집 코드의 흐름:

```python
parser = TableParser()
parser.feed(html)
```

1. `TableParser()`로 표 읽기 도구를 만든다.
2. `feed(html)`에 받아온HTML 문자열을 전달한다.
3. 시작 태그가 나오면 `handle_starttag`가 호출된다.
4. 셀 안의 글자를 만나면 `handle_data`에서 모은다.
5. 셀이 끝나면 글자를 행에 넣고, 행이 끝나면 표에 넣는다.

결과는 사람 눈에 보이는 표가 아니라, 행마다 값이 담긴 리스트다. 실제CU의 과거 공시 수집자료에서2024년 평균매출 표의 전국 행은 다음처럼 기록되어 있다.

```python
['전체', '18,255', '633,837', '26,455']
```

이것을 열 제목과 함께 읽으면 가맹점 수18,255개, 점포당 평균매출633,837천원이라는 뜻이다. 마지막 열은 면적당 매출이다. **열의 위치만 보고 의미를 추측하면 안 되고 표의 헤더·단위를 같이 확인해야 한다.**

이 파서는 병합 셀의 위치를 모두 펼쳐 복원하지 않는다. `rowspan`·`colspan`이 있으면 검토 필요 상태를 남긴다. 일반 `normalize_table` 함수는 병합 검토가 필요한 표를 자동 분석 대상으로 바꾸지 않는다. 공식 지역점포 표는 별도의 전용 해석 코드에서 헤더와 열의 묶음을 확인해 읽었다.

수집에 실패하면 오류로 기록하거나 반환한다. 실패를 실제0으로 바꾸지 않는다. 네트워크에 따라 실행 결과가 달라질 수 있어 발표 시연은 이미 수집한자료를 읽는 방식으로 준비했다.

**발표 문장:** “웹 화면의 표를 행과 열의 리스트로 바꿨습니다. 병합 셀이나 표 구조가 복잡한 경우는 자동 확정하지 않고 별도로 확인했습니다.”

## 4. 가져온 문자열을 분석 가능한 값으로 바꾼 방법

웹에서 받은`'18,255'`는 숫자처럼 보여도 문자열이다. 다음 순서로 바꾼다.

```python
value = int(raw.replace(',', ''))
```

- `replace(',', '')`: 쉼표를 제거해서`'18255'`로 만든다.
- `int(...)`: 문자열을 정수18255로 바꾼다.
- 정수로 바꿔야 합계·비교·나눗셈을 할 수 있다.

금액은 원자료의 단위를 먼저 확인했다.

```python
633837 * 1000
```

633,837천원은633,837,000원이다. 화면에서 반올림한 억·만원 표시보다 천원 단위의 표 값을 사용한 경우 그 정밀도를 기록했다. 이는 원자료가1원 단위까지 제공됐다는 뜻은 아니다.

연도는 등록일이 아니라 **실제 표에 쓰인 실적연도**로 고른다.2025년에 등록된 정보공개서 안에2024년 실적이 들어 있을 수 있다.

실제 지역집계 해석 코드:

```python
years = [int(x.replace('년', '')) for x in t[0][1:]]
j = years.index(year) if year in years else None
```

- `t[0]`: 표의 첫 행이다.
- `[1:]`: 첫 칸의`지역`을 빼고 나머지 연도 제목을 읽는다.
- `years`: 예를 들어2025·2024·2023 같은 연도 목록이다.
- `index(year)`: 필요한 연도가 목록의 몇 번째인지 찾는다.
- 필요한 연도가 없으면`None`으로 두고 다른 연도의 숫자를 대신 쓰지 않는다.

해당 공정위 점포 표는 각 연도가`전체점포·가맹점·직영점` 세 칸으로 구성되어 있었다. 그래서 `r[2 + 3*j]`로 그 연도의 가맹점 수를 읽었다. 여기의3은 통계공식이 아니라 **당시 표 구조에 맞춘 열 간격**이다. 사이트 구조가 달라지면 이 코드는 다시 확인해야 한다.

`0`과 결측도 구분한다.0은 원본의 값, `None` 또는JSON의`null`은 값이 없는 상태다. 원본0을 그대로 보존했다고 그0이 실제 시장 매출0임을 검증한 것은 아니다.

## 5. 원본 엑셀의 빈칸에 어떻게 연결했는가

`build_region_plan.py`는 수집결과와 엑셀을 비교해 **보완계획**을 만든다. 한 항목에는 파일명, 시트명, 셀주소, 브랜드, 연도, 입력할 값, 근거URL이 들어간다.

예를 들어CU2024년 서울 가맹점 수를 넣는 작업은`03_지역집계`의 해당CU행·서울열에2,861을 연결하는 방식이다. 전국18,255와경기4,961도 같은 연도·가맹점 기준으로 읽었다.

핵심 조건:

```python
if v(col, row) is not None:
    continue
```

이미 값이 있으면 건너뛴다. 실제 공시와 다른 기존값을 발견해도 마음대로 바꾸지 않고 차이 내역을 따로 남겼다. `None` 여부로 검사하므로 기존0도 덮어쓰지 않는다.

검토 과정에는 자동 비교와 사람이 확인하는 과정이 함께 있었다. 모든 창업비용·매출·지역값이 같은 하나의 정규화 함수로 자동 생성된 것은 아니다.

이전 지역집계 보완 단계의 기록에는 숫자를 넣은30칸과 당시 확인한 공식 표에서 값을 확보하지 못한21칸이 있다. 이는 그 단계·그 파일의 기록이다. 이후 사용자가 수정해 첨부한 파일의 상태까지 이 숫자로 단정하지 않는다. 현재 첨부에는 추가 숫자와`미공계` 같은 텍스트도 있으며, 원본 보존JSON은 이것도 그대로 담는다.

**발표 문장:** “수집자료와 엑셀을 브랜드·연도·지역으로 연결했습니다. 기존값은 보존하고, 빈칸에 넣을 값과 출처를 별도 계획으로 만든 뒤 반영했습니다.”

## 6. 엑셀은 어떻게 저장했고 왜 복잡한 방식을 썼는가

원래 파일에는 이미11개 시트와 수식·서식이 있었다. 새 엑셀을 처음부터 다시 만들어 저장하면 기존 모양이나 일부 기능이 달라질 수 있었다. 그래서 최종 보완 과정은 **기존 엑셀을 복사하고 지정 셀의 내용만 바꾸는 방식**을 사용했다.

`.xlsx`는 내부적으로 여러XML문서가 들어 있는ZIP 구조다. 초보자는 “엑셀 한 파일 안에 시트와 서식 등의 부품이 들어 있다” 정도로 이해하면 된다.

- `author_review.mjs`: 기존 엑셀을 읽고 값 입력·재계산·미리보기를 확인하는 JavaScript 작성 도구다. 당시 실행환경의`@oai/artifact-tool`을 사용했다. Python 기본 라이브러리나 사용자의PC에 기본 설치된 도구가 아니다.
- `preserve_workbooks.py`: 최종적으로 원본ZIP 부품을 복사하고 허용한 빈 셀의 숫자만 입력한다.
- `fill_only_blanks`: 빈 셀이 아니면 중단한다. 원본과 출력 경로가 같아도 중단한다.
- `verify_preservation`: 허용된 셀을 되돌렸을 때 원본XML과 같은지 비교한다. 다른 시트·서식 등도 비교한다.

따라서 **최종 원본보존 엑셀을 `pandas.to_excel()` 한 줄로 만들었다고 발표하면 실제 작업과 다르다.** pandas는 분석에 사용했고, 원본 보존 저장은 별도 코드가 맡았다.

원본 보존을 검사할 때 파일 전체의 해시가 수정 전후 같아야 하는 것은 아니다. 빈칸을 채웠으니 수정본 전체 해시는 달라질 수 있다. 변경하지 않은부품과 허용 범위 밖 셀이 같은지를 확인했다. 반면 JSON 변환처럼 읽기만 하는 작업은 원본 전체 해시가 같아야 한다.

## 7. 분석은 어떤 규칙으로 했는가

엑셀과 웹 표를 계산에 사용할 때는 다음처럼 한 줄의 의미를 정리한다.

|year|industry|brand|region|value|
|---:|---|---|---|---:|
|2024|편의점|CU|전국|633837000|

여기서`value`가 점포 수인지 매출인지 혼동하지 않도록 매출표`sales`, 점포표`stores`를 분리했다.

`pd.DataFrame(...)`은 이러한 행 목록을 계산 가능한 표로 만든다. 한 행은 하나의 관측이고, 열은year·industry처럼 항목이다. 실제 구분키는 연도·업종·브랜드·지역이다.

### 7-1. 같은 조건만 선택

```python
mask = frame.year.eq(year) & frame.region.eq(region)
```

`eq`는 같은지 비교한다. `&`는 두 조건을 모두 만족해야 한다는 뜻이다.2024년 서울과2025년 전국을 한 묶음으로 평균내지 않기 위해 먼저 조건을 고른다. 전국과 서울·경기는 서로 겹치므로 합산하면 중복된다.

### 7-2. 업종별 평균

실제 함수의 핵심:

```python
select(sales, year, region).groupby('industry', as_index=False).agg(
    mean_annual_revenue=('value', 'mean'),
    brand_count=('brand', 'nunique')
)
```

- `groupby('industry')`: 같은 업종의 행을 묶는다.
- `agg`: 묶음마다 어떤 계산을 할지 지정한다.
- `mean`: 매출을 모두 더해 포함된 행 수로 나눈다.
- `nunique`: 서로 다른 브랜드가 몇 개인지 센다.
- `as_index=False`: 업종을 결과의 일반 열로 남긴다.

이 평균은 **수치가 있는 선정 브랜드의 점포당 평균매출을 다시 단순평균한 값**이다. 점포 수로 가중한 업종 전체 시장평균이 아니다. 확인 브랜드 수를 함께 보여야 한다. 원본에 잘못된0이 들어 있으면 단순평균도 영향을 받으므로 입력값 검토가 별도로 필요하다.

### 7-3. 합계

```python
sum(min_count=1)
```

같은 조건에서 관측된 점포 수를 합산한다. `min_count=1`은 집계 대상값이 모두 결측이면0으로 확정하지 않도록 한다. 다만 현재 로더는 숫자만 표에 넣으므로 아예 관측행이 없어진 경우까지 이 옵션 하나로 모두 해결하지는 않는다.

### 7-4. 매출 순위와 평균 대비 차이

```python
s['industry_rank'] = s.groupby('industry')['value'].rank(
    method='min', ascending=False
)
s['industry_mean'] = s.groupby('industry')['value'].transform('mean')
s['difference_from_mean'] = s['value'] - s['industry_mean']
```

- `rank`: 같은 업종 안에서 순위를 붙인다.
- `ascending=False`: 큰 매출이1위다.
- `method='min'`: 공동1위 두 개가 있으면 다음은3위다.
- `transform('mean')`: 업종평균을 해당 업종의 각 행 옆에 붙인다.
- 평균대비차이=브랜드매출−업종평균. 양수면평균보다높고 음수면낮다.

### 7-5. 전년 비교

`merge`로 같은 브랜드·지역의2024와2025 자료를 연결한다. 두 연도의 값이 모두 있어야 증감과 증감률을 계산한다.

- 증감액=2025매출−2024매출
- 증감률=(2025매출−2024매출)÷2024매출
-2024매출이0이면 나눗셈을 할 수 없으므로 성장률을 만들지 않는다.
- 한 연도의 값만 있으면 반대 연도를 복사하거나 추정하지 않는다.

원본05_매출비교는 브랜드마다 한 연도만 적힌 경우가 있다. 그래서 전년 비교함수가 있어도 모든 브랜드의 실제 전년 비교가 가능한 것은 아니다.

## 8. 비용·운영이익은 어떻게 계산했는가

여기에는 두 가지 방식이 있다.

**A. 엑셀 기본 시뮬레이션:** `00_가정`의 비용 비율을 매출에 곱한다.

**B. Python 예산 함수:** 사용자가 입력한 비용 금액을 매출에서 뺀다.

둘을 혼동하면 “웹에서 점포의 실제 재료비·인건비까지 수집했다”는 잘못된 설명이 된다. 이번 CU 예시의 비용은 A 방식이다.

CU의 2024년 기존 연매출은 633,837,000원이다. 원본 편의점 비율은 재료비 65%, 인건비 8%, 임차료 5%, 기타 5%다.

|항목|계산식|결과|
|---|---|---:|
|재료비|633837000 × 0.65|411,994,050원|
|인건비|633837000 × 0.08|50,706,960원|
|임차료|633837000 × 0.05|31,691,850원|
|기타운영비|633837000 × 0.05|31,691,850원|
|운영비 합계|위 4개 비용 합계|526,084,710원|
|예상 운영이익|633837000 − 526084710|107,752,290원|
|예상 이익률|107752290 ÷ 633837000|0.17 = 17.0%|

17%는 비용 비율 합계 83%의 나머지다. 가정 비율이 고정된 같은 업종에서는 매출이 달라도 같은 17%가 나올 수 있다. 이를 실제 점포 수익성이 동일하다는 증거로 쓰면 안 된다.

실제 원본 수식:

```excel
='05_매출비교'!C3
```

다른 시트의 CU 연매출 셀을 가져온다. `!` 앞은 시트명, 뒤는 셀 주소다.

```excel
=IF($C3="","",$C3*VLOOKUP($B3,'00_가정'!$A$5:$F$8,2,FALSE))
```

- `IF`: 매출이 비어 있으면 결과도 비워 두고, 값이 있으면 계산한다.
- `$C3`: C열을 고정한 3행 셀이다.
- `$B3`: 업종이 적힌 셀이다.
- `VLOOKUP`: 가정표 첫 열에서 해당 업종을 찾아 같은 행의 값을 가져온다.
- `2`: 가정표의 두 번째 열인 재료비율을 뜻한다.
- `FALSE`: 업종명이 정확히 일치하는 행을 찾는다.
- 매출 × 찾아온 비율이 재료비다.

Python의 `budget_profit`은 입력된 4개 필수 비용을 확인하고 합계를 낸다. 월 비용이면 12배로 연환산한다. `Decimal`은 금액의 소수 계산 오차를 줄이는 데 사용한다. 연매출이 0일 때 이익률, 이익이 0 이하일 때 회수기간을 정상 숫자처럼 계산하지 않는다.

창업비용은 처음 준비할 때 드는 비용이고, 운영비는 운영 기간 중 발생하는 지출이다. 창업비용 전액을 매년 운영비로 자동 차감하지 않았다. 로열티·수수료·감가상각 등은 입력 비용에 포함되어야 하며, 빠지면 이익이 과대평가될 수 있다.

서울 비중은 서울 매장 수 ÷ 전국 매장 수다. CU 2024년은 2,861 ÷ 18,255 ≈ 0.156724 = 15.7%다. 서울·경기를 합한 수도권 비중은 이 식과 다르다.

## 9. 값이 있는데 왜 엑셀에 빈칸이 보였는가

엑셀 수식에는 두 가지 정보가 있다.

1. 계산 방법인 수식: 예를 들어 `=C3/E3`
2. 마지막으로 계산해 파일에 저장된 결과: 예를 들어 `0.1567`

수식이 있어도 두 번째 저장값이 비어 있거나 오래된 0이면, 엑셀 뷰어와 일부 프로그램에서 빈칸·0으로 보일 수 있다. 일부 숫자 서식은 0을 감추므로 저장값 0도 화면상 빈칸처럼 보일 수 있다.

이번 작업에서는 서울 비중과 CU 운영이익 행에서 이 문제가 발생했다. 처음에는 수식을 보존했지만 저장 계산 결과까지 갱신하지 못했고, 이후 별도 코드로 수정했다.

- `fix_seoul_share.py`: 숫자가 있는 행의 서울 ÷ 전국 값을 확인해 저장 계산 결과를 갱신했다.
- `fix_cu.py`: CU행의 연매출·비용·운영비 합계·이익·이익률 8칸을 기존 수식 기준으로 갱신했다.

비용을 새로 웹에서 찾아 넣은 수정이 아니다. 기존 수식·가정과 맞는 저장 결과를 만든 수정이다.

엑셀에는 여러 셀이 수식 패턴을 공유하는 ‘공유수식’도 있다. 이때 값의 타입만 수정하려다 수식의 부가 정보를 건드리면 다른 행까지 영향을 받을 수 있다. CU 수정 과정에서는 검증 중 이 문제를 발견했고 최종 수정본에서는 공유수식 정보를 유지했다. 수식 문자열이 보인다는 이유만으로 전체 파일이 정상이라고 판단하면 안 된다.

**발표 문장:** “화면의 빈칸이 모두 데이터 미수집은 아니었습니다. 수식과 저장된 결과가 달라 생기는 경우를 구분하고, 입력값과 직접 계산한 결과를 대조해 보정했습니다.”

## 10. JSON은 어떻게 만들고 검증했는가

JSON은 프로그램이 읽기 좋은 텍스트 형식이다. 엑셀 화면을 그림으로 저장하는 것이 아니라, 시트·행·열·값을 리스트와 이름표 형태로 저장한다.

**이 프로젝트에는 서로 다른 JSON 구조가 있다.**

|구분|시트값을 담는 위치|용도|
|---|---|---|
|이전 원본보존·분석용|`sheets[].cells["C3"].value`|기존 `analysis.py`가 읽는 형태|
|마지막 엑셀 직접 변환용|`sheets[].data` + `index` + `columns`|엑셀 모든 셀을 일대일로 보관하는 형태|

마지막 변환은 `convert_excel.py`로 수행했다. 새 웹수집이나 추정을 하지 않고, 사용자가 마지막에 첨부한 엑셀을 그대로 읽었다.

```python
formula = openpyxl.load_workbook(source, data_only=False)
cached = openpyxl.load_workbook(source, data_only=True)
```

두 번 여는 이유:

- `data_only=False`: `=SUM(...)`처럼 수식 자체를 읽는다.
- `data_only=True`: 수식의 저장 계산 결과를 읽는다.
- 이 옵션이 수식을 새로 계산해 주는 것은 아니다.

한 시트의 `index`는 엑셀 행 번호 1, 2, 3…, `columns`는 A, B, C…, `data`는 각 칸의 값이다. `formula_results`에는 수식 셀별 저장 계산 결과를 따로 둔다. 원본 빈칸은 null, 숫자 0은 0, 오류는 원래 오류 문자열로 유지한다. 날짜·시간은 JSON 문자열로 변환한다.

실제 저장 코드:

```python
json.dumps(out, ensure_ascii=False, indent=2, allow_nan=False)
```

- `json.dumps`: Python의 딕셔너리·리스트를 JSON 문자열로 바꾼다.
- `ensure_ascii=False`: 한글을 읽을 수 있는 형태로 저장한다.
- `indent=2`: 들여쓰기를 넣는다.
- `allow_nan=False`: 표준 JSON에 맞지 않는 NaN·Infinity가 있으면 중단한다.
- 이후 UTF-8로 파일에 쓴다.

저장한 JSON을 다시 읽어 모든 셀의 값·수식·저장 결과를 엑셀과 비교했다. 또 변환 전후 엑셀 해시를 비교해 원본을 바꾸지 않았는지 확인했다. 검증은 “엑셀과 변환 JSON이 같다”는 검증이지, “엑셀의 모든 숫자가 실제 공시와 일치한다”는 검증이 아니다.

### 분석용 JSON과 보존용 JSON을 섞으면 생기는 문제

기존 `analysis.py`는 `cells`를 찾는다. 마지막 변환 JSON에는 `cells`가 없다. 이번 확인에서도 마지막 JSON을 그대로 기존 로더에 넣으면 `KeyError: 'cells'`가 발생했다.

그래서 “마지막 JSON 4개를 기존 API 폴더에 복사하면 바로 분석된다”고 말하지 않는다. 구조를 맞추는 연결 단계가 필요하다. 함께 제공한 발표 실습 노트북은 마지막 JSON을 읽어 기존 분석 함수가 받는 DataFrame을 만드는 별도 시연용 연결 부분을 넣었다. **이 연결 부분은 이번 발표 준비를 위해 추가한 것이며, 이전 구현이라고 주장하지 않는다.** 원본 분석 코드는 수정하지 않았다.

## API까지 이어지는 흐름

API는 화면이 계산 함수를 호출할 수 있게 만든 접점이다. 실제 `api.py`에는 다음 경로가 있다.

|경로|역할|
|---|---|
|GET `/summary`|연도·지역 조건으로 집계|
|GET `/sales`|매출 비교·순위|
|GET `/validation`|데이터 검사 결과|
|POST `/budget`|입력 비용에 따른 예산손익|

예를 들어 화면에서 연도와 지역을 선택하면 서버가 해당 함수를 실행하고 결과를 JSON 응답으로 준다. API가 웹스크래핑을 매번 실행하는 구조는 아니다. 기존 `data()`는 파일을 읽는다. 화면과 실제 연결·배포까지 끝났다고 말할 근거는 없다. 이번 발표 준비에서는 API 서버를 실행하지 않았고, 분석 함수와 오프라인 시연을 실행 검증했다.

|매개변수|함수를 실행할 때 전달받는 입력 이름|
|`return`|함수가 계산한 결과를 호출한 곳에 돌려줌|
|`None`|Python에서 값이 없다는 표시|
|`null`|JSON에서 값이 없다는 표시|
|인덱스|어느 행·대상을 가리키는지 식별하는 기준|
|컬럼|매출·브랜드처럼 같은 종류의 항목을 담은 열|
|캐시|여기서는 수식을 마지막으로 계산해 저장한 결과|
|검증 `assert`|조건이 맞는지 확인하고 틀리면 중단|
