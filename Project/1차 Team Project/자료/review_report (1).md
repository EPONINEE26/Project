## 이름 매칭과 보류 기준

- 기준 JSON의 id/name을 그대로 유지했습니다. 연도별 매출·점포 수 통계는 위치 목록에 사용하지 않았습니다.
- Unicode NFKC·공백/기호 제거·영문 대소문자 통일을 적용했습니다. 원본 상호명은 출력 보조 필드에 보존했습니다.
- 현재 이름, 한영 병기에서 분리한 이름, english_name을 비교했습니다. 모든 괄호를 약칭으로 간주하지 않았습니다. 과거 명칭과 메가커피 계열 약칭은 검토 후보로만 사용했습니다.
- 규칙 통과는 정규화 전체 이름 일치 또는 이름이 시작 부분에 있고 뒤에 24자 이하의 ‘…점’ 지점명이 붙은 경우입니다. 4자 미만, 숫자 이름, 지정 일반어 목록, 여러 브랜드 후보는 자동 승인하지 않았습니다.
- 지점명 접미사 규칙도 휴리스틱입니다. 임의의 일반어 전부를 식별하는 사전은 아니므로 오매칭 가능성이 남습니다. 4자 이상 이름도 가맹 관계를 보장하지 않습니다.
- 상호의 중간 부분에 브랜드가 있다는 이유만으로 지도에 넣지 않았습니다. 중간 부분 3자 이상, 시작 부분의 짧은 이름은 검토 후보가 될 수 있습니다. 한글과 영어 음역, 알려지지 않은 별칭, 오탈자를 전부 탐지하지는 못합니다.
- CSV 대분류/중분류/소분류와 기준 업종의 조합을 확인했습니다. 업종이 다르거나 업종 대응 규칙이 없는 브랜드의 이름 후보는 버리지 않고 보류했습니다. 기타 서비스·이사·운송 등 일부 업종의 지도 배열이 비어 있는 이유에는 보류 기준도 포함됩니다. 빈 배열은 매장이 없다는 뜻이 아닙니다.
- 후보 미발견은 사용한 이름 규칙에서 후보를 못 찾았다는 뜻입니다. 비가맹점·폐점 확정이 아닙니다. alias_rules.csv와 처리 코드에 실제 적용 규칙이 있습니다.

## 중복 및 매장 구분

원본 39개 필드 전체가 같고 비어 있지 않은 bizesId도 같은 행만 중복 제거할 수 있도록 처리했습니다. 이번 입력에는 해당 완전 중복 및 동일 ID 충돌이 없었습니다. 제거 내역 파일은 헤더만 있습니다. 다른 ID의 같은 주소·건물·좌표는 병합하지 않았습니다.

후보 브랜드별로 같은 지역·도로명주소·건물명·숫자 좌표가 겹치는 행을 별도로 모았습니다. 같은 층·호여도 같은 매장으로 확정하지 않았습니다. 다른 지점/층/호 및 여러 층을 쓰는 매장 가능성을 원본 정보와 함께 보류했습니다. 좌표가 조금 다르거나 주소 표기가 다른 중복까지 모두 식별한 것은 아닙니다.

동위치 보류에는 아직 약한 이름 후보도 포함되므로, 모든 묶음을 실제 중복이라고 해석하지 마세요. 원본 행과 보류 사유는 review_candidates.jsonl.gz에 남겼습니다. 지도용 데이터는 자동 보류 규칙을 통과한 행만 포함합니다.

## 좌표와 누락 값

전체 입력의 lat/lon을 숫자·유한값·지구 범위(lat ±90, lon ±180)·참고 국내 사각 범위(lat 33~39.5, lon 124~132)로 검사했습니다. 이번 검사에서 문제 행은 0개입니다. 이 사각 범위는 행정경계 검사가 아닙니다. **실제 주소를 지오코딩해 좌표와 대조하지 않았습니다.**

출력 좌표는 JSON 숫자입니다. 주소/건물명/지점명/층/호 등의 원본 빈 문자열은 그대로 유지했습니다. 가짜 값이나 건물명·층·호 추정값을 만들지 않았습니다. 기준 브랜드 name이 null인 19개 항목(카페 1개 포함)은 원본 null을 유지하며 이름 매칭에 쓰지 않았습니다.

marker_title은 원본 bizesNm에 brchNm이 이미 들어 있으면 상호명만 쓰고, 그렇지 않으면 두 값을 공백으로 연결했습니다. 공식 지점명으로 교정한 값은 아닙니다.
